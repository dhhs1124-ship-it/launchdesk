# LaunchROAS 첫 버전

별도 Vercel 프로젝트의 Root Directory를 `launchroas`로 설정하는 정적 사이트다.
현재 공개 배포 전이며, 검색 색인은 막는다. 별도 도메인은 정해지지 않았다.

- 기존 LaunchDesk Supabase 프로젝트의 **publishable** 키와 Auth를 공유한다.
- 이메일·비밀번호 로그인과 회원가입을 제공한다. 두 사이트의 인증 저장소는 Origin별로 독립적이므로 런치데스크 연결 관리에 들어갈 때 같은 이메일로 로그인해야 한다. 소셜 로그인은 아직 제공하지 않는다.
- 회원가입은 런치데스크 약관·개인정보처리방침에 필수 동의해야 한다. 동의 이력은 `user_policy_consents`에 저장·재확인한다. 이메일 인증이 필요한 경우에는 인증 후 첫 로그인에서 다시 동의를 받고 기록한다. 정책 버전은 루트의 `policy-consent-core.js`와 이 디렉터리의 동명 파일을 함께 갱신해야 한다.
- 연결 추가/해제는 기존 LaunchDesk `#/account`에서 처리한다. `주문 동기화 · 다시 조회`는 선택된 Cafe24 쇼핑몰에 대해 `cafe24-orders-sync`를 호출하고 데이터를 다시 읽는다. 연결이 없으면 저장된 데이터만 다시 읽는다.
- Cafe24 주문금액은 취소·환불·미입금 미차감이고, Meta 구매금액은 Meta 귀속 기준이다. 두 값을 합산하지 않는다.
- 주문은 선택 기간이 `orders_synced_from` 범위에 들어올 때만 숫자를 표시한다. 건수가 조회 한도를 초과하면 불완전한 합계를 표시하지 않는다.
- 운영 현황은 오늘·어제·이번 달·선택 날짜의 Cafe24 주문과 Meta 광고 요약, 오늘의 운영 브리핑, 광고 상태, 월간 요약, 세팅 대행 안내, 연결 상태, 광고 기록을 보여준다. 기간 변경은 저장된 데이터를 읽고, 주문 동기화는 새로고침 버튼에서만 한다. 선택 기간이 `orders_synced_from` 기록 범위 밖이면 0건으로 단정하지 않는다.
- 연결 상태는 화면 우측 상단의 Cafe24·Meta 상태로 축소했다. 운영 브리핑·광고 상태·월간 현황은 숫자 중심 카드로 보여준다. `meta-adset-insights`를 사용해 선택 기간의 캠페인 아래 광고 세트 성과를 보고, 세트를 펼쳐 개별 광고 성과를 조회한다. 조회 한도로 결과가 잘렸으면 해당 결과를 계산에 연결하지 않는다.
- 개별 광고의 `마진 계산 연결`은 원화 계정일 때만 선택 기간의 **광고비**를 계산기에 가져온다. Meta 귀속 구매 건수는 상품별 주문 수가 아니므로 참고 정보로만 보여 주고, 해당 상품 주문 수는 사용자가 입력한다. 상품 원가와 판매 조건도 직접 확인해야 한다. 쇼핑몰/계정 전환 시 광고 목록과 기존 계산 입력을 비운다.
- 미리보기 피드백 반영: PC 왼쪽 메뉴는 스크롤 시 고정하고 운영 화면의 헤더·핵심 지표 간격을 줄였다. 광고별 성과와 운영 브리핑을 나란히 놓고 광고 세트는 비용순 상위 3개만 먼저 표시하며, 광고 기록은 펼쳐서 본다. `마진 계산 연결`은 통화와 관계없이 클릭 가능하다. 원화 계정이면 광고비를 자동 입력하고, 외화 계정이면 환율을 임의로 적용하지 않고 원화 광고비를 직접 입력하도록 안내한다.
- 광고 기록은 LaunchDesk와 같은 `tool_records`/`ad_log`를 사용한다. 수동 기록은 선택된 쇼핑몰에 묶고, Meta 하루 합계는 원화 계정만 동일 쇼핑몰·광고계정·날짜당 1건으로 저장한다. 도매처 카드는 의도적으로 제외했다. 세팅 대행 접수와 계정 연결 변경은 같은 계정으로 로그인한 LaunchDesk 화면으로 안내한다.
- 마진 계산은 루트 `margin-calc.js`의 동일 계산 코어 복사본을 쓴다. 간편/상세 조건, 광고비 비율·금액, 예시, 기존 계산 기록(`tool_records`/`margin_calc`)을 포함한다. A상품 광고 손익은 광고 전 주문당 예상 잔액 × 사용자가 입력한 광고 유입 주문 수 − 해당 상품의 광고비 총액으로 별도 계산해 주문당 광고비를 중복 차감하지 않는다. Meta 광고계정 합계와 Cafe24 주문을 자동으로 같은 상품에 귀속시키지 않는다. 루트의 `margin-calc.js`, `ops-period-core.js`, `adlog-meta.js`를 바꾸면 복사본도 함께 갱신해야 한다.

이메일 인증 링크는 별도 Redirect URL을 지정하지 않아 현재 Supabase 기본 Site URL인 런치데스크로 열린다. 가입 안내에서 인증 후 LaunchROAS로 돌아와 로그인하도록 설명한다. 배포 전에는 새 Origin의 Edge Function CORS 허용 목록과 정책 적용 범위를 점검한다. 소셜 로그인 도입 시 Auth Redirect URL과 OAuth 연결 경로도 정리한다.
