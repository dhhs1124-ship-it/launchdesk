# LaunchDesk Beta 30일 검증 실행 계획

> 상태: 실행 계획 문서. 코드/화면은 이 문서로 변경하지 않는다. 여기 등장하는
> 이벤트명(`signup_completed` 등)은 실제 구현 시 기존 프로젝트가 이미 쓰고 있는
> GA4 `gtag('event', ...)` 방식(예: `app.js`의 `page_view`/`chapter_start`,
> `tools.js`의 `margin_calculator_use`)과 같은 스타일(snake_case)로 맞췄다 — 새
> 트래킹 시스템을 도입하는 게 아니라 기존 방식을 확장하는 전제다.

---

## 1. Beta의 목적

Beta 기간(출시 후 30일) 동안 **모든 기능을 무료로 제공**한다. 이 기간의 목적은
가입자 수를 늘리는 것 자체가 아니라, 아래 3가지를 검증하는 것이다.

1. 실제 사용자가 Cafe24/Meta를 **연결**하는가 (연결 자체가 "이 도구가 내 운영에
   필요하다"는 신호)
2. 연결한 사용자가 운영 대시보드를 **반복해서** 보는가 (일회성 호기심이 아니라
   반복 사용 가치가 있는가)
3. 위 두 가지가 확인되면, 이게 **향후 유료화할 가치가 있는 제품인가**

**초기 타겟**: Cafe24 자사몰을 운영하거나 준비 중이고, Meta 광고를 사용하거나
사용할 예정인 소형 쇼핑몰 운영자. (오픈마켓 전용/광고 안 쓰는 운영자는 이번
Beta의 핵심 타겟이 아니다 — 유입은 막지 않되, 검증 대상 퍼널의 중심은 아니다.)

---

## 2. 핵심 사용자 퍼널

```
유입
  → 회원가입
    → 로드맵 사용
      → 쇼핑몰 등록
        → Cafe24 연결
          → 실제 주문 데이터 확인
            → Meta 연결
              → 광고 성과 확인
                → 7일 내 재방문
                  → (향후) Pro 전환
```

이 문서의 이벤트 설계(4장)·목표 수치(6장)·GO/ITERATE/STOP 판단(7장)은 전부 이
퍼널의 각 단계 전환율을 기준으로 한다.

---

## 3. Activation 정의

| 구분 | 정의 |
|---|---|
| **기본 Activation** | 쇼핑몰 등록 + Cafe24 연결 + 실제 주문 데이터 대시보드 확인 |
| **Meta Activation** | Meta 연결 + 실제 광고 성과 조회 성공 |
| **North Star** | Cafe24 또는 Meta를 연결한 사용자가 **다음 주에도** 운영 대시보드를 다시 확인하는 것 |

North Star를 "연결" 자체가 아니라 "다음 주 재방문"으로 잡은 이유: 연결은 호기심
만으로도 한 번은 할 수 있지만, 일주일 뒤 다시 보러 온다는 건 실제로 이 데이터를
운영에 쓰고 있다는 더 강한 신호이기 때문이다.

## 4. 측정 이벤트

### 초기 이벤트 후보

| 이벤트명 | 왜 필요한가 |
|---|---|
| `signup_completed` | 퍼널의 시작점. 이후 모든 전환율의 분모가 되는 기준 |
| `roadmap_started` | 콘텐츠(로드맵)가 첫 진입 후크로 작동하는지 확인 |
| `roadmap_completed` | 로드맵을 끝까지 본 사용자가 실제 연결까지 이어지는지 비교하기 위한 중간 지표 |
| `store_created` | 기본 Activation의 1단계. "내 쇼핑몰 정보를 등록할 만큼 진지한가" |
| `cafe24_connected` | 기본 Activation의 핵심 — 실제 데이터 연결 의지가 있는지 확인하는 가장 중요한 이벤트 |
| `orders_synced` | 연결은 했지만 동기화가 실패/지연되는 이탈 구간이 있는지 별도로 확인하기 위함(연결과 실제 데이터 확인은 다른 단계) |
| `meta_connected` | Meta Activation의 시작. Cafe24만 쓰는 사용자와 광고까지 보는 사용자를 구분 |
| `dashboard_viewed` | North Star(재방문) 판단의 기준 이벤트 — 발생 시각을 기준으로 "가입일/연결일 대비 며칠 뒤인지"를 계산 |
| `meta_insights_viewed` | Meta Activation의 완료 — 연결만 하고 실제로 성과를 안 보는 사용자와 구분하기 위함 |
| `setup_inquiry_started` | 연결이 어려운 사용자가 대행 서비스로 이탈하는지 확인 — Cafe24/Meta 연동 자체가 진입장벽인지 판단하는 보조 신호 |
| `setup_inquiry_completed` | 위 문의가 실제 제출까지 이어지는 비율 — UI 문제로 중간 이탈하는지 확인 |

### 향후 이벤트 (Beta 기간엔 발생량이 적어도 미리 계측만 걸어둠)

| 이벤트명 | 왜 필요한가 |
|---|---|
| `wholesale_clicked` | 도매처 찾기 기능이 실제로 클릭되는 기능인지 — 별도 검증 대상이라 이번 Beta 핵심 지표에는 넣지 않되, 초기 관심도만 참고로 수집 |
| `subscription_started` | Free→Pro 전환이 시작되면 그 순간부터 전환 소스(어떤 사용 패턴을 가진 사용자가 전환하는지)를 역추적하기 위해 지금부터 이벤트만 미리 정의 |
| `subscription_cancelled` | 이탈 이유 분석 — 정식 과금 시작 전이라도 이벤트명은 미리 확정해두는 게 나중에 코드 일관성에 유리 |

모든 이벤트는 가능하면 `user_id`(로그인 사용자 식별자)를 함께 남겨서, 한 사용자의
퍼널 진행 순서를 이후에 재구성할 수 있게 한다.

## 5. 유입 추적

각 세션에서 가능한 경우 아래 3가지를 함께 기록한다.

```
source=meta
medium=paid_social
campaign=beta_launch_01
```

| 채널 | source | medium |
|---|---|---|
| Meta 유료 광고 | `meta` | `paid_social` |
| Instagram 오가닉(프로필 링크 등) | `instagram` | `organic_social` |
| 블로그/콘텐츠 | `blog` | `content` |
| 네이버/구글 검색(SEO) | `naver` / `google` | `organic_search` |
| 직접 유입(URL 직접 입력, 북마크) | `direct` | `none` |
| 커뮤니티/카페 공유 | (커뮤니티명) | `referral` |

가입 시점의 `source/medium/campaign`을 `signup_completed` 이벤트에, 그리고
가능하면 사용자 레코드 자체에도 한 번 저장해서, 이후 어떤 채널로 들어온 사용자가
실제 연결·재방문까지 이어지는지 채널별로 비교할 수 있게 한다. (동일 세션 내
첫 방문 시점의 UTM 파라미터를 기준으로 삼고, 이후 세션에서 값이 없으면 최초
값을 유지하는 first-touch 방식을 기본으로 한다 — 여러 채널을 오가는 사용자의
기여도를 마지막 채널로만 단순화하지 않기 위함.)

## 6. 초기 30일 내부 목표

> **주의: 아래는 업계 표준이 아니라 LaunchDesk 자체 검증을 위한 내부 실험
> 기준이다. 절대적인 성공 기준으로 단정하지 않는다.** 실제 결과가 아래 수치와
> 다르게 나오는 것 자체가 정상적인 검증 과정이며, 7장의 GO/ITERATE/STOP 판단은
> 이 숫자 하나만으로 내리지 않는다.

가입자 100명 기준(예시):

| 단계 | 내부 목표(예시) | 전환율 환산 |
|---|---|---|
| 쇼핑몰 등록 | 40명+ | 가입자 대비 40%+ |
| Cafe24 연결 | 20명+ | 가입자 대비 20%+ |
| 실제 대시보드 확인 | 15명+ | 가입자 대비 15%+ |
| Meta 연결 | 5~10명+ | 가입자 대비 5~10%+ |
| 7일 내 재방문 | 8~10명+ | 가입자 대비 8~10%+ |

가입자가 100명이 아니면 위 숫자를 그대로 쓰지 말고 비율(%) 기준으로 환산해서
본다.

## 7. GO / ITERATE / STOP 판단

| 판단 | 어떤 숫자를 볼 때 | 어떤 행동을 할지 |
|---|---|---|
| **GO** | Cafe24/Meta 연결률과 7일 재방문률이 6장 목표 대비 의미 있는 수준으로 나옴(예: 연결률 20%+, 재방문률 8%+ 동시 충족) | 기능 강화 + 광고 예산 확대. 이 시점부터 Free/Pro 분리(11장) 설계를 본격화 |
| **ITERATE** | 가입은 목표만큼 나오는데, Cafe24 연결률 또는 7일 재방문률이 목표에 뚜렷이 못 미침(예: 연결률 10% 미만이거나 재방문률 3% 미만) | 온보딩 흐름/핵심 가치 제안(밸류 프로포지션) 수정 — 8장 Week 2 작업(이탈 구간 분석)에 집중, 광고비는 늘리지 않고 유지 |
| **STOP 또는 큰 방향 수정** | 유입·가입은 되는데 Cafe24 연결과 재방문이 거의 발생하지 않음(예: 연결률 5% 미만이면서 재방문률도 거의 0에 수렴) | 기능을 더 추가하기보다, "이 제품이 푸는 문제가 실제로 존재하는가" 자체를 재검토. 10장 사용자 인터뷰를 온보딩 개선이 아니라 가치 제안 재검토 목적으로 다시 진행 |

세 판단 모두 **연결률과 재방문률을 함께** 봐야 한다 — 가입자 수만으로는 절대
판단하지 않는다(1장의 Beta 목적과 동일한 이유).

## 8. 30일 실행 일정 (Day 1~30)

### Week 1 (Day 1–7) — Beta 오픈 · 계측 · 유입 시작
- **Day 1**: Beta 오픈. `signup_completed`~`meta_insights_viewed` 전 이벤트가
  실제로 발생하는지 실환경에서 1차 스모크 테스트(운영자 본인 계정으로 전
  퍼널 직접 실행)
- **Day 2**: 이벤트 수집 정상 여부 재확인(GA4 실시간 리포트 등). UTM 파라미터가
  실제로 붙어 들어오는지 확인
- **Day 3–4**: 유료 광고(9장) 소액 집행 시작 + SEO/블로그/Instagram 오가닉
  유입 병행 시작
- **Day 5–7**: 채널별 최초 유입/가입 수 확인. 이벤트 자체가 안 찍히는
  기술적 문제가 있다면 이번 주 안에 반드시 수정(2주차부터는 데이터 신뢰가
  중요해지므로)

### Week 2 (Day 8–14) — 이탈 구간 분석 · 온보딩 수정
- **Day 8–9**: 가입 → 쇼핑몰 등록 → Cafe24 연결까지 단계별 이탈률 집계
- **Day 10–11**: 이탈이 가장 큰 구간 특정 (예: 등록은 하는데 Cafe24 연결에서
  대부분 이탈하는지, 아니면 가입 자체에서 이탈하는지)
- **Day 12–13**: 특정된 구간의 UX 수정(문구/버튼 위치/설명 부족 등 — 이번
  단계는 큰 기능 추가가 아니라 막힘 해소가 목적)
- **Day 14**: 수정 반영 후 이번 주 전환율을 1주차와 비교

### Week 3 (Day 15–21) — 재방문 · 반복 사용 분석
- **Day 15–16**: `dashboard_viewed` 재발생 간격 분석 — 연결 후 며칠 만에
  돌아오는지, 안 돌아오는 사용자와의 차이가 무엇인지
- **Day 17–18**: 재방문한 사용자가 대시보드에서 실제로 무엇을 보는지(주문
  현황만 보는지, Meta 성과까지 보는지) 확인
- **Day 19–21**: 반복 사용 이유가 확인된 기능이 있다면 그 부분만 먼저
  강화(이번 단계도 새 기능 추가보다 기존 기능 보강 우선)

### Week 4 (Day 22–30) — 인터뷰 · 유료화 의향 조사 · 최종 판단
- **Day 22–24**: Activation된 사용자(기본 Activation 또는 Meta Activation
  완료자) 중심으로 사용자 인터뷰 진행(10장 질문 활용)
- **Day 25–26**: 가격 질문 포함 유료화 의향 조사 — 단, 가격 응답만으로
  판단하지 않는다(10장 참고)
- **Day 27–28**: 인터뷰·설문 결과와 정량 지표(4~6장 이벤트 기준)를 함께 정리
- **Day 29**: 30일 전체 지표를 7장 판단표에 대입해 GO/ITERATE/STOP 초안 도출
- **Day 30**: 최종 판단 확정 및 다음 30일 계획(또는 방향 전환) 문서화

## 9. 광고비 테스트

초기 유료 광고는 **30만원 내외의 소규모 테스트**로 가정한다. 목적은 곧바로 Pro
결제를 만드는 게 아니라, 아래 흐름 각 단계까지 도달하는 데 드는 비용을
파악하는 것이다.

```
방문 → 가입 → Cafe24 연결 → 재방문
```

### 봐야 할 수치

| 지표 | 계산 방법 | 왜 보는가 |
|---|---|---|
| 방문자당 비용 | 광고비 ÷ 방문자 수 | 채널 자체의 트래픽 단가 확인(CPC/CPM과 유사한 개념을 유입 전체로 확장) |
| 가입자당 비용 | 광고비 ÷ `signup_completed` 수 | 단순 트래픽이 아니라 "가입까지 이어지는" 비용 — 랜딩/가치 제안이 광고 소재와 맞는지 간접 확인 |
| Cafe24 연결 사용자당 비용 | 광고비 ÷ `cafe24_connected` 수 | 이 제품의 핵심 Activation까지 도달하는 실질 비용 — 이 숫자가 유료화 이후 손익 계산의 기준이 됨 |
| 재방문 사용자당 비용 | 광고비 ÷ (7일 내 재방문한 사용자 수) | North Star까지 도달하는 데 드는 비용 — 향후 Pro 전환 비용 추정의 출발점 |

30만원 규모에서는 표본이 작아 통계적으로 확정적인 결론을 내리기 어렵다 —
"이 채널이 확실히 좋다/나쁘다"보다는 "다음 테스트에 얼마를 더 써볼 가치가
있는가" 정도의 방향성 판단에 사용한다.

## 10. 사용자 피드백

Beta 사용자에게 물어볼 질문(4주차 인터뷰/설문, 8장 참고):

- 가장 유용했던 기능은 무엇인가요?
- 가장 불편했던 기능은 무엇인가요?
- (재방문 사용자에게) 다시 들어오는 이유는 무엇인가요?
- 없어도 되는 기능이 있다면 무엇인가요?
- 추가로 필요한 기능이 있다면 무엇인가요?
- 유료화된다면 돈을 낼 만한 기능은 무엇인가요?
- 월 9,900원이라면 계속 사용하시겠어요?
- 월 14,900원이라면 계속 사용하시겠어요?

**주의**: 가격 질문(월 9,900원/14,900원)에 대한 응답만으로 수요를 판단하지
않는다 — "얼마면 쓰겠다"는 응답과 실제 결제 행동 사이에는 흔히 큰 차이가
있다("가격에 대한 응답 편향"). 가격 질문은 방향 참고용으로만 쓰고, 실제
판단은 정량 지표(4~7장)와 "가장 유용했던 기능"/"다시 들어오는 이유" 응답을
더 우선한다.

## 11. Free → Pro 전환 방향

**Beta 기간**: 모든 기능 무료.

**정식 출시 이후**: Free / Pro 분리.

| Free 후보 | Pro 후보 |
|---|---|
| 로드맵 | Meta 광고 분석 |
| 자료실 | 기간 비교 |
| 도매처 찾기 | 그래프 |
| 계산기 | 자동 인사이트 |
| 기본 Cafe24 운영현황 | 이상 감지 |
| | 운영 알림 |
| | AI 분석 |

이 구분은 6~7장의 Activation 지표와 연결된다 — Free 쪽은 "기본 Activation"에
필요한 최소 기능(쇼핑몰 등록·연결·기본 현황 확인)까지를 커버하고, Pro 쪽은
"Meta Activation" 이후의 심화 분석·자동화 기능으로 나뉜다. 실제 경계선은 30일
검증 결과(어떤 기능이 재방문을 만드는지)를 보고 최종 확정한다 — 이 표는 시작
가설이지 확정안이 아니다.

## [30일 종료 후 판단표]

| 지표 | GO | ITERATE | STOP/방향 수정 |
|---|---|---|---|
| Cafe24 연결률(가입자 대비) | 20%+ | 10~20% | 10% 미만 |
| 7일 내 재방문률(가입자 대비) | 8%+ | 3~8% | 3% 미만 |
| 인터뷰 정성 반응 | "다시 쓸 이유"가 구체적으로 나옴 | 기능은 인정하나 재방문 동기가 약함 | 핵심 가치 제안 자체에 의문 제기 다수 |
| 다음 행동 | 기능 강화 + 광고 확대(11장 Free/Pro 분리 본격화) | 온보딩/핵심 가치 수정 후 재검증 | 기능 추가 중단, 가치 제안 재검토 |

두 지표(연결률·재방문률)가 서로 다른 칸에 해당하면, 더 낮은 쪽 판단을
우선한다 — 예: 연결률은 GO 구간인데 재방문률이 STOP 구간이면 전체 판단은
ITERATE 이상으로 올리지 않는다(6~7장 원칙과 동일하게, 연결만으로는 검증이
끝났다고 보지 않는다).
