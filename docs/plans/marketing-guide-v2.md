## 1. 광고 기본 용어 `[기본 개념]`

| 용어 | 정의 | 계산식 | 무엇을 보는 지표인가 |
|---|---|---|---|
| ROI | 투자 대비 수익률 | (이익 − 비용) ÷ 비용 × 100 | 비용을 제외한 실제 순이익 기준 효율 |
| ROAS | 광고비 대비 매출(전환가치) 비율 | 전환 매출 ÷ 광고비 × 100 | 광고 자체의 매출 효율 (이익률은 반영 안 됨) |
| CPM | 노출 1,000회당 비용 | 광고비 ÷ 노출수 × 1,000 | 노출 단가, 경쟁 강도의 간접 지표 |
| CPC | 클릭 1회당 비용 | 광고비 ÷ 클릭수 | 소재·타겟팅이 클릭을 얼마나 저렴하게 만드는가 |
| CTR | 노출 대비 클릭 비율 | 클릭수 ÷ 노출수 × 100 | 소재의 첫인상(썸네일/카피)이 얼마나 매력적인가 |
| CPA | 전환(구매 등) 1건당 비용 | 광고비 ÷ 전환수 | 원하는 행동을 얻는 데 드는 실제 비용 |
| CVR | 방문/클릭 대비 전환 비율 | 전환수 ÷ 클릭수(또는 방문수) × 100 | 유입된 사람이 실제로 사는 비율 |
| AOV | 평균 객단가 | 총매출 ÷ 주문건수 | 한 번 살 때 얼마나 많이 사는가 |

`[2026 업데이트]` Meta 광고 관리자의 리포트 지표명·기본 표시 단위(예: ROAS를 배수로
보여줄지 %로 보여줄지)는 UI 개편으로 자주 바뀐다. `[변경 가능]` — 캠페인을 세팅하기
직전에 실제 화면에서 명칭을 다시 확인할 것.

## 2. Meta 광고 구조 `[기본 개념]`

```
Campaign (캠페인)   — 광고 목표(objective) 단위. 예산을 캠페인 레벨에서 관리하는

  └ Ad Set (광고 세트) — 타겟팅 · 예산 · 노출 위치 · 일정 단위
```

범위를 계속 넓혀가는 추세라, 위 3단 계층에서 사람이 직접 만지는 옵션이 Ad Set
레벨에서 Campaign 레벨로 점점 올라가고 있다. `[변경 가능]` — 정확히 어떤 옵션이
캠페인/세트 중 어디에 있는지는 세팅 직전 화면에서 다시 확인.

## 3. 광고 목표 — Traffic vs Sales `[기본 개념]` / `[LaunchDesk TIP]`

- **Traffic**: 웹사이트 방문·링크 클릭 자체를 최적화. 저비용으로 반응(클릭률)을
  넓게 확인하는 데 유리.
- **Sales**: 실제 구매(전환 이벤트)를 최적화. 픽셀/CAPI로 구매 데이터가 어느 정도
  쌓여야 학습이 원활하다.

`[LaunchDesk TIP]` 상품이 여러 개고 아직 뭐가 반응이 좋을지 모르는 초기 단계에서는,
Traffic(또는 오픈마켓/버티컬 플랫폼의 저비용 노출)으로 먼저 반응을 넓게 확인하고,
반응이 확인된 상품만 Sales 목적으로 좁혀서 확장하는 방식이 예산 효율이 좋다 —
`[운영자 경험, 출처: 기존 STEP07 마케팅 챕터 "채널 역할 나누기"]`의 "오픈마켓·버티컬
광고 = 상품 테스트용" / "Meta 등 타겟팅 광고 = 확장 실행용" 원칙과 같은 방향이다.

**단, 이게 항상 정답은 아니다.** 아래 경우엔 처음부터 Sales로 시작하는 편이 나을
수 있다:
- 이미 리타겟팅에 쓸 수 있는 방문자/구매자 모수(픽셀 이벤트 데이터)가 있는 경우
- 예산이 너무 적어 Traffic 단계에서도 유의미한 학습량 자체가 안 나오는 경우
- 재구매·구독형처럼 애초에 트래픽보다 전환 최적화가 목적에 더 맞는 경우

"무조건 Traffic → Sales 순서"로 단정하지 말 것.

## 4. 초보자 Meta 광고 세팅 `[기본 개념]` + `[운영자 경험]`

**픽셀 / CAPI**
`[운영자 경험, 출처: 자료실 "메타 픽셀 연동" 가이드]` 실제 연동 절차: 인스타그램
프로필에 페이스북 페이지 연결 → Business Suite에서 광고 계정 생성 → 데이터
소스에서 픽셀 생성 → 쇼핑몰 플랫폼(예: 카페24) 고급설정에 코드 직접 입력 →
판매채널에서 채널 연동 승인.
`[기본 개념]` CAPI(Conversion API)는 브라우저 픽셀만으로 잡히지 않는 전환(광고
차단기, iOS 프라이버시 정책 등으로 유실되는 신호)을 서버 쪽에서 보완하는 방식.
`[2026 업데이트]` 서드파티 쿠키/브라우저 추적 제한이 계속 강화되는 흐름이라 CAPI의
중요도는 갈수록 커지는 추세다. `[변경 가능]` — 사용 중인 쇼핑몰 플랫폼이 CAPI를
어떤 방식(자체 연동/앱/수동)으로 지원하는지는 플랫폼별로 다르고 자주 바뀌므로 세팅
직전 최신 문서로 확인할 것.

**Purchase 이벤트** `[기본 개념]` — 결제 완료(주문 완료) 페이지에 설치하는 표준
이벤트. 캠페인 목적을 Sales로 잡을 때 이 이벤트가 최적화 기준이 된다.

**예산** `[변경 가능]` — Meta의 일일 최소 예산 정책은 통화·상품군에 따라 달라지고
개편도 잦다. 최신 검증 필요.

**타게팅** `[2026 업데이트]` — 세부 관심사 타게팅을 직접 좁히기보다 광범위 타게팅 +
Advantage+ 자동화에 맡기는 방식이 최근 권장되는 추세다. `[변경 가능]` — Meta의 공식
권장 방식은 계속 바뀌므로 캠페인 세팅 시점의 최신 가이드를 다시 확인할 것.

**소재** `[운영자 경험, 출처: 기존 STEP07]` "반응 확인된 상품만 영상 소재로 집중
투입" / "사진보다 사용 영상에서 성과가 좋은 경우가 많음."

**판매 캠페인과 트래픽 캠페인 분리** `[LaunchDesk TIP]` 3장의 원칙을 그대로
적용 — 두 캠페인을 같은 예산 안에서 섞지 말고, 목적이 다르면 캠페인 자체를
분리해서 각자의 지표(Traffic=CTR/CPC, Sales=CPA/ROAS)로 따로 평가한다.

## 5. 광고 성과 읽는 방법 `[운영자 경험]`

퍼널 순서: 노출 → **CTR** → 클릭(**CPC**/**CPM**) → 장바구니 → 체크아웃 → 구매
(**CPA**) → **ROAS**.

`[운영자 경험, 출처: 기존 STEP07 "CTR만으로 광고를 판단하지 않기"]` 실제 판단
순서로 제시했던 원칙:

> 실제 이익 → 구매 수 → CPA → ROAS → 장바구니/결제 진입 → CTR → CPC → CPM

`[운영자 경험, 출처: 동일]` — CTR만 보면 낮아 보여도 유지할 가치가 있었던 실제
사례:

| 지표 | 값 |
|---|---|
| 광고비 | 약 9만원 |
| 노출 | 약 11,741회 |
| 클릭 · CTR | 90회 · 0.77% |
| CPC | 약 1,000원 |
| 전환율 | 약 5.56% |
| ROAS | 약 522% |

"CTR 2% 미만이면 중단" 같은 절대 기준은 없다는 게 이 사례의 핵심 — CTR 하나만
보고 광고를 끄지 말고, 항상 구매/ROAS까지 함께 봐야 한다.

## 6. 광고 진단 패턴 `[LaunchDesk TIP]` (`[운영자 경험]` 근거 포함)

아래 패턴은 전부 **"가능성이 높음" / "먼저 확인"** 형태로만 서술한다. 실제 원인은
상품·타겟·시즌에 따라 다르므로, 아래는 확정 진단이 아니라 확인 순서를 좁혀주는
가이드다. (기존 제품의 4분면 진단 도구 a~d와 대응 관계를 함께 표기)

| 패턴 | 가능성 높은 원인 | 먼저 확인할 항목 | 추천 행동 | 기존 진단 도구 대응 |
|---|---|---|---|---|
| **CTR 높음 / 장바구니 낮음 / 구매 낮음** | 광고 소재와 랜딩(상세페이지) 사이 기대 불일치, 모바일 로딩/UX 문제일 가능성 | 광고 클릭 직후 도착 화면이 광고 내용과 일치하는지, 모바일 첫 화면(가격·옵션) 노출, 페이지 로딩 속도 | 랜딩페이지-소재 일치도 개선, 상세페이지 상단 재구성 | 도구 결과 `a`와 유사 |
| **CTR 높음 / 장바구니 높음 / 구매 낮음** | 체크아웃 단계 이탈(배송비 노출 시점, 결제수단 제한, 신뢰요소 부족)일 가능성 | 장바구니→배송정보→결제 각 단계 이탈률, 배송비가 언제 노출되는지, 리뷰/보증 요소 유무 | 체크아웃 플로우 단순화, 배송비 사전 고지, 리뷰/신뢰요소 보강 | 도구 결과 `a`의 "결제 UX/배송비" 항목과 연결 |
| **CTR 높음 / 구매 높음** | 소재·상품·가격 정합성이 좋은, 지금 가장 좋은 상태일 가능성 | 예산 확장 여력, 소재 노출 빈도(피로도) | 예산 확대, 유사 소재 추가 제작, 소재가 지치기 전 교체 준비 | 도구 결과 `d`와 동일 |
| **CTR 낮음 / 반응 없음** | 소재 자체의 매력 부족, 또는 타겟-상품 불일치일 가능성 | 썸네일·영상 도입부 3초, 타겟 설정과 상품 궁합, 카피 | 썸네일/도입부 교체 테스트, 타겟 재점검 | 도구 결과 `b`와 동일 |
| **CTR 낮음 / 장바구니 있음 / 구매 없음** | 유입 자체가 적어 판단하기엔 모수가 부족할 가능성이 먼저이고, 그다음으로 구매 직전 확신 요소 부족일 가능성 | 절대 유입 수가 통계적으로 의미 있는 수준인지부터 확인, 그 다음 장바구니→구매 이탈 지점 | 예산/기간을 늘려 모수부터 확보, 확신 요소(리뷰·보장) 보강, 리타겟팅으로 별도 유도 | 도구 결과 `c`(CTR 낮지만 CVR 높음)와는 다른 패턴 — 혼동 주의 |

## 7. 파트너십 광고 `[기본 개념]` / `[2026 업데이트]`

`[기본 개념]` Meta의 파트너십 광고(Partnership Ads, 구 Branded Content Ads)는
크리에이터가 올린 오가닉 게시물(릴스 등)에 브랜드가 별도 소재 제작 없이 광고
예산을 태워 확장하는 기능이다. 크리에이터가 브랜드의 광고 계정에 "파트너십 광고
권한"을 부여해야 브랜드 쪽에서 그 게시물을 소재로 선택할 수 있다.

절차 개요:
1. 크리에이터 섭외 및 릴스 제작(8장 참고)
2. 크리에이터가 자신의 계정에 오가닉 게시
3. 크리에이터가 브랜드 광고 계정에 파트너십 광고 권한 부여
4. 브랜드가 광고 관리자에서 해당 게시물을 소재로 선택해 캠페인 집행
